# Hutter compression guide

This site explains lossless compression using the codecs in the [Hutter repository](https://github.com/bbondy/hutter). It covers the underlying concepts, the Rust implementation of each teaching codec, the archive formats, and how to make and test changes. A separate research section follows the project's competitive Hutter Prize candidate. It assumes no prior knowledge of compression.

The repository is an experimental workspace for the [Hutter Prize](https://prize.hutter1.net/). The Rust codecs work on arbitrary byte files. The current research branch studies a pinned published compressor, but the project has not reproduced a full prize-valid result locally.

## Read in order

The [course sequence](course/path.md) starts with files and bits, then explains how Huffman, LZ77, and predictive codecs represent the same data in different ways. Later chapters trace those ideas through the Rust source. Concepts are defined before they are used; the codebase chapters are separate from the introductory material.

## What the codecs have in common

A compressor reads bytes and writes an archive. A decoder reads that archive and must reproduce the original bytes exactly. Some codecs describe repeated bytes with shorter codes; some point backward to repeated sequences; others predict the next byte or bit from what came before.

The encoder and decoder must use the same model state at each step. When a model learns from a byte, the decoder must update it at the same point as the encoder. The [archive walkthrough](codebase/flow.md) shows where this happens in the Rust code.

The [interactive examples](lab.mdx) use simplified models to illustrate individual ideas. The algorithm pages distinguish those examples from the repository's actual archive implementations.
